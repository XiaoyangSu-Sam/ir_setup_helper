# 个人耐力调教助手 · Endurance Lab

面向 Ferrari 296 GT3、纽博格林 Gesamtstrecke VLN 干地的本机调教工作台。目标是积极的车头响应、可控的车尾和稳定的长段节奏。比赛总时长与单次驾驶／燃油段分别记录。

## Windows 安装版

从 [GitHub Releases](https://github.com/XiaoyangSu-Sam/ir_setup_helper/releases) 下载适合 64 位 Windows 的 EXE 安装包，双击安装。安装包含 Python 运行环境，使用当前 Windows 用户权限。安装后从开始菜单打开 **IR Setup Helper**，默认浏览器会打开本机界面 <http://127.0.0.1:19392>。选择开始菜单里的 **Stop IR Setup Helper** 可以停止后台服务。

安装版的数据目录为 %LOCALAPPDATA%\IRSetupHelper\data，升级和卸载会保留这里的记录与档案。源码版沿用项目内的 data 目录与 19391 端口。两个版本的数据各自保存。安装包旁的 .sha256 文件可用于核对下载完整性。

在 Windows 本机构建时，先安装 [Inno Setup](https://jrsoftware.org/isinfo.php)，再在项目根目录运行以下命令。

    python -m pip install -r requirements.lock.txt pyinstaller==6.22.3
    powershell -File scripts/build_windows.ps1 -Python python

安装包和校验文件生成在 dist 目录。发布与项目版本号匹配的 v* 标签时，GitHub Actions 会构建并验收单独调教版和合装版，把两份 EXE 和各自的校验文件放在同一个 Release。

### 调教与报名合装

在 Windows 本机构建时，用报名助手原来的干净分享 ZIP 作为第二个组件。下面以 0.4.1 预览分享包为例。

    powershell -File scripts/build_windows.ps1 -RegistrationPackage "D:\path\iRacingAssistant-0.4.1-preview.zip"

生成的 IRacingTools 安装包会在开始菜单的 **iRacing Tools** 中提供 **IR Setup Helper** 和 **iRacing Registration Assistant**。调教使用 19392，报名使用 19390。合装可以升级先前安装的调教版。报名由用户从开始菜单打开，已有报名预约和手机访问配置保存在原来使用的报名助手目录。合装后的报名入口使用安装目录下的 registration\data，两个数据目录各自保留。报名助手运行期间，安装程序会暂缓覆盖安装或卸载，待用户退出报名助手后可继续。

合装的报名功能沿用原版。Mazda 个人赛支持预约，耐力赛车队功能仍用于查看赛事和准备队伍。本地构建只接收分享 ZIP 中获准的程序文件，并校验文件清单。已有独立报名助手运行时，请从原来的托盘入口继续使用。

报名助手升级时，从新分享包导出干净的运行组件。下面以报名版本 0.4.1-preview 为例。

    python -X utf8 scripts/stage_registration.py "D:\path\registration-share.zip" build/windows --export-runtime dist/iracing-registration-runtime-0.4.1-preview.zip
    Get-FileHash dist/iracing-registration-runtime-0.4.1-preview.zip

把运行组件附到同一 GitHub 仓库的 registration-v0.4.1-preview 预发布，再更新 packaging/registration-release.json 中的版本和 SHA-256。下一次套件发布会用这份固定版本重建合装版。既有版本使用其发布时锁定的报名组件。

## 教学视频参考

导入自己的 .ibt 后，在「弯道与参考圈」中选好布局和分段，将参考来源切换到「教学视频」。已有本机视频可以直接播放，暂停后点「取当前帧」填入时刻。网页视频可保留来源链接，并手填原播放器时刻。先标记与本机分段相同的入段、弯心和出段，再按照画面填写刹车、开油和速度读数。整圈时间、已知赛道条件和走线笔记可选填。

核对过的分段可对照速度读数。确认视频连续且原速度为 1× 后，还可对比分段时间，并按三个地标估算视频踏板位置。本机视频由浏览器播放，资料库只存标记、读数和来源。视频调教与未显示的条件标为未知，观察结果只用于驾驶对照。

## 0.6：带数值和来源的试调候选

当前 `ir_suggest.htm` 的入弯／弯中推头，可以生成 **Front ARB blades：45 → 30 deg**。工具同时保留 Large 防倾杆规格、其他基准值和 45° 回退值，显示预期作用、可能代价、验证观察点，并提供本轮调整卡下载。它仍是试调候选，不是已通过游戏 Tech 或已证明更快的设置。

以前仅依据主程序版本不同而全盘拒绝历史参数。现在优先同版本参数；不足时，仅允许有明确复核条目的版本组合和参数。当前复核严格限定 Ferrari 296 GT3、2026.10.01.01 → 2026.11.02.01、实际读取车辆包 2026.09.25.02、同布局；前 ARB 还要求规格相同。来源记录仍保留旧版本号，不伪装成当前版本采集。

复核依据是本机组件版本与官方 Patch 2 说明；这是工程兼容推断，不是官方保证。不会把完整范围或步长猜出来，不外推未观测档位，也不会放宽跨版本圈速对比或 Tech 规则。车辆包／主程序更新、布局不同、关联规格不同或缺失时停止沿用该复核。

纯手感描述新增“入弯推头”，与“转向响应慢”及“弯中推头”区分。资料仍不足时，默认提示“先保持当前设置，无需你操作”，技术诊断放在展开项里。用户不需要填参数表或做人工检查声明。

## 0.5：以文件和官方基准为起点

工作台默认“文件基准（无需启动游戏）”。直接使用已导入 IBT 的设置快照，或展开“读取本机文件或上传设置”：

- 自动发现本机 Ferrari 设置目录中的 `.htm/.html`，选择后读取；也可以上传 `.htm/.html` 或 `.ibt` 并设为基准。重复内容不重复存档。
- 对想使用的官方基准，在 Garage → iRacing Setups 加载，点击 **Export** 导出 `.htm`，然后交给助手读取。之后可离线查看设置和规划调整，不需要驾驶圈，也不需要保持游戏连接。
- `.sto` 当前只识别文件存在，**尚不能解码参数**。上传时会给出 Export 路径，不会假装成功。工具不会向外部解码服务发送文件。
- HTML 作为文本解析，不执行脚本。保留原始字段、单位、来源与未知项；只有明确识别的 Ferrari 296 参数参与数值计算。未知单位仍展示原文，不猜测转换后可输入的档位。
- 文件未注明版本时，按用户偏好自动采用本机当前安装版本；从 iRacing 服务注册信息定位安装目录并只读 version_system.txt，必要时尝试运行中的 SDK。无需手输，也不借用最近遥测的旧版本。文件自带的明确版本保持不变。文件没注明布局时，侧栏仅作为使用目标，并明确说明它不证明适用性。可识别的布局不匹配会拒绝应用。
- 文件名含 official／endurance 不构成官方身份的证明。官方基准也是个人试调起点，不自动代表个人适配或改动后通过 Tech。
- 游戏实时读取仅是可选来源，不再用“未连接游戏”阻挡文件基准。

已使用真实 `ir_suggest.htm` 验证 Garage 导出解析，并修复含逗号的前轴标题与 TC 字段。旧导入会自动重读保留的文件，不必重新上传；原始文件和基准 ID 不变。文件缺少的版本自动按当前安装版本处理，保留推定来源；游戏更新后重新识别，不借用其他记录的旧版本。已有 IBT 也可直接离线使用。下面 0.4 的接口说明保留，来源选择以本节为准。

## 0.4：让工具处理工程信息

面向不会调车的人，日常流程是：描述哪里不好开 → 点击“给我一个调整方案” → 查看具体目标和回退值 → 试跑后选择感觉改善、恶化或没有区别。无需填写最小值、最大值、档位步长、实际改动复述或人工 Passed Tech 声明。

- **凭感觉**：不要求驾驶曲线。工具仍须读取设置，才知道应从什么值改到什么值。
- **凭数据／感觉 + 数据**：使用已有驾驶记录，并把观测、原因假设和建议实验分开。
- **游戏版本**：从本机安装自动读取，不要求手填；按当前版本处理未标版本导出是用户指定的使用假设，不当作文件原生版本证明。
- **当前设置**：可选 Windows SDK 共享内存只读适配器；只有选择实时来源才会访问。自动识别车型、布局、游戏版本、设置快照与可用的路面条件。默认使用文件基准，历史 IBT 设置可作为离线起点。
- **数值资料**：自动查找同车型、同布局、同游戏版本实际出现过的参数值，按独立的保守实验幅度上限选择目标。历史观测不是完整合法档位表，不推断未知步长，不外推未见过的档位。资料不足由工具承担，不再让用户填表。
- **安全检查**：当前只完成来源、上下文、单位与幅度预检。尚未接通游戏整套 Passed Tech 结果，不能保证建议组合通过游戏检查，也不会把试跑记录、反馈或人工勾选冒充游戏结果。这一能力仍待实现。
- **跑后反馈**：只需选择手感，备注可留空。工具查找新快照是否出现目标值，仍保留其他参数变化与逐圈一致性的未知项。无法自动核实的轮胎使用、交通和逐圈设置使效果归因保持“证据不足”；用户无需代替工具背书。

首次无数据时，可读取或上传 Garage 设置导出，无需驾驶遥测。首版官方基准仍需在游戏中加载；官方 `.sto` 数值、完整合法范围以及官方配置自动鉴定尚未接通。现有官方实例可查阅，但已取消面向普通用户的手工参数录入表。

“参数与搭配”提供 10 个参数的增减作用和 3 组联动说明，附官方手册页码。它是可追溯规则库，不是已学会整套最优搭配的模型。尾翼和车高等联动仍需数据与游戏检查支持。

## 直接使用

1. 双击 **启动耐力调教助手.cmd**，打开 <http://127.0.0.1:19391>。
2. 默认“凭感觉”：说哪里不好开，或选择一个通俗现象。比赛目标是可选项。
3. 工具尝试读取设置；有足够参数依据时显示“当前值 → 目标输入值”和回退值。文件方案针对所选基准，不要求连接游戏；实际应用需从同一份基准出发。
4. 保存方案后，在“试跑验证”记录感受。助手不自动操作游戏、不修改 `.sto`；游戏安全检查自动接入尚未完成。
5. 有遥测时可补充前后驾驶段对比；每个条件组前后至少三圈有效圈，失误片段仍保留。缺少自动核实项时不宣布设置已验证。
6. 双击 **停止耐力调教助手.cmd** 关闭后台服务。仅关闭浏览器不停止监测。

本机之前已导入 52 份 IBT，所有车型共 27 个有效完整圈；Ferrari＋VLN 尚无足够完整圈完成真实的调教改善验收。现有同版本快照只覆盖部分参数值，不能保证每一种感受现在都能生成具体数值。例如当前前防倾杆为 30° 时，缺少同版本同布局更低档位的记录，工具会明确提示自身资料不足。

## 录制与数据

- 默认通过 Windows 实际“文档”位置定位 `iRacing/telemetry`，支持重定向／OneDrive 文档。可在“驾驶记录 → 采集与目录设置”指定另一个目录。
- 游戏内按 **Alt + L** 开启遥测，确认 Telemetry 指示。结束试跑并结束记录后，以实际 `.ibt` 文件状态确认采集成功。目录存在或页面上的“监测中”不代表游戏正在录制。
- 后台每 15 秒扫描一次，每轮最多导入三份新记录。近期或正在变化的文件等待稳定；磁盘头未完成的文件继续等待。按内容哈希去重，不会重复导入复制的相同文件。
- 可以上传自己的历史 `.ibt` 或有权使用的参考记录；文件仅保存在本机助手目录。原始遥测和游戏设置不被改写。
- `data/recordings` 保存包含原始通道与标准化单位的 Parquet；`data/coach.duckdb` 保存来源、会话元数据、圈／驾驶段、快照、实验和偏好。数组通道也保留。速度用 km/h，方向盘用度，燃油用 L。
- 快照来自 IBT 会话元数据，不证明每一圈设置一致。缺失值不补成零，不把缺失通道当作没有事故。
- 备份时先停止助手，再复制 `data` 和 `config`。原始 IBT 请单独保留。

## 看懂分析结果

“弯道与参考圈”按距离展示速度、制动、油门和转向。无参考圈时仍可观察本段，并查看多次通过的分布；不会估计最佳刹车点或虚构时间损失。参考圈用于描述差异，燃油、天气及驾驶条件仍需核对。没有可信位置数据时不做确定的走线诊断。

首版已用两份本机记录核对 **GP 左右连续弯整组** 和 **第一个左弯** 的距离窗口。其他区域使用文件内官方计时分段，弯中边界是待人工校准的草稿，不当作已确认的实际弯道。可在“校准弯道／连续弯分段”修改距离；`verified` 只有位置核实后才勾选。配置和核对来源见 `config/nurburgring_vln.json`。布局 ID、路径或长度不匹配时不套用该窗口。

验证会比较车型、布局、驾驶员、游戏版本和赛道版本，按燃油、赛道／气温、路面湿度、胎种、配重及动力限制分组。每个可比组前后都至少三圈，才判断初步变化。进出站、事故、冲出赛道和不完整片段保留在稳定性记录里；有效圈用于代表圈速与波动。方向输入变化次数包含正常驾驶修正，不能直接当作失控次数。

配对试跑后，“试跑验证”会显示调校计时墙。可在完整参考圈和理论最佳圈间切换，点击官方计时段查看时间差，再选已校准的弯道查看刹车点、减速度、入弯／弯心／出弯速度，以及按距离对齐的速度、刹车和油门曲线。理论最佳圈使用各组最快赛段相加，可追溯各段原始圈。绿色表示相对已导入可比历史圈的个人最佳，紫色要求遥测中的全场正式圈速结果可核对。模拟记录可独立检查界面。

“初步改善”需要可比组的代表圈速改善超过观察波动，且记录内失误占比未上升；主观手感另行记录；当前界面不再依靠人工声明补全自动检查缺失项，因此无法核实的对比保持证据不足。“证据不足”可能来自圈数少、条件不同、通道缺失或差异未稳定超过波动。高低油量覆盖、已记录驾驶段时长分别显示，短试跑不会被标为已验证适合三小时比赛。长段配速变化也不能直接称为轮胎衰退。

调教规则位于 `config/setup_rules.json`，参数知识位于 `config/parameter_knowledge.json`，链接到 [Ferrari 296 GT3 官方手册](https://s100.iracing.com/wp-content/uploads/2024/06/Ferrari-296-GT3-V4.pdf)。目前提供有限的前防倾杆、前束、TC、尾翼候选实验和高速稳定性检查，不宣称能自动求解整套最快设置。参数具体数值优先来自同版本已观测值，或限定车型／布局／车辆包与参数的明确兼容复核候选；这些候选不等于完整合法范围或整车检查通过。解释来自模板，LLM 不参与数值计算。

## 开发与故障排查

本机已配置 Python 3.12 虚拟环境；它依赖原 Python 安装，不是可随意搬迁的独立安装包。重装环境需要 Python 3.11+：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
```

若页面未打开，先检查 `data/runtime/server.log`，再用浏览器访问本机地址。重复启动复用同一实例；停止入口只通知本项目启动器，不按模糊进程名终止其他程序。服务只监听 `127.0.0.1`，不会开放给局域网。

维护命令需先停止助手，避免与运行中的 DuckDB 写入连接冲突：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m endurance.cli import --report data/acceptance-import.json
.\.venv\Scripts\python.exe -X utf8 -m endurance.cli summary
.\.venv\Scripts\python.exe -X utf8 -m pytest -q
```

测试覆盖二进制解析与数组、单位、缺失通道、损坏／未完成文件、记录断续、布局与环境拒绝比较、三圈门槛、失误保留、范围与版本约束、去重持久化、目录监测，以及完整 Streamlit 实验流程。测试数据与用户数据隔离。
